# 북토크 캘린더 일일 갱신 절차

하루 두 번(오전 9시 무렵·저녁 6시, 서울 시간) Claude Code 루틴이 매번 **새 세션**에서 이 문서를 따른다. 이 문서가 유일한 지시서다.
검색은 WebSearch / WebFetch로 하고, 병합·중복 제거·점수 계산·오늘 할 일 정하기는 `collect.py`가 맡는다.

## 사용량 원칙 (꼭 지킨다)

이 루틴은 사용자의 Claude 사용 한도 안에서 돈다. 같은 결과를 덜 쓰고 얻는 것이 목표다.

- **이미 아는 행사는 다시 조사하지 않는다.** 오늘의 계획(`--brief`)에 '이미 아는 행사' 목록이 나온다.
  검색 결과에 그 행사가 보이면 건너뛴다. 상세 검색도, inbox 기록도 하지 않는다.
- **오늘 계획에 나온 미션·검색어·페이지만** 조사한다. 미션마다 회차 간격(`every`)으로 돌고, 검색어도 실행마다 돌아가며 바뀐다.
  나머지 미션은 쉬는 회차다. 계획에 없는 미션을 스스로 더 하지 않는다.
- 검색 예산: 미션당 계획에 나온 검색어 + **새로 발견한 행사 한 건당 상세 검색 1회**까지. 페이지 열람은 계획에 나온 것만.
- `config.toml`, `site/data/events.json`, `site/calendar.ics`는 **열어 읽지 않는다.** 필요한 내용은 `--brief`가 다 보여 준다.
- 하위 에이전트(Agent 도구)를 띄우지 않는다. 검색 결과를 요약하려고 파일에 옮겨 적었다가 다시 읽지 않는다.

## 0. 준비

저장소는 **루틴 설정(claude.ai 루틴 화면의 저장소 선택)** 으로 세션에 붙어 있다. 루틴 세션에서는 `add_repo`를 쓸 수 없다.

```bash
cd urban-octo-palm-tree   # 루틴이 붙여 둔 저장소 디렉터리
git checkout main && git pull origin main
rm -f collector/inbox.json
git push --dry-run origin HEAD:refs/heads/_push_check   # push 권한 미리 확인 (실제로 만들지 않음)
```

- 저장소 디렉터리가 없거나 `git push --dry-run`이 403 등으로 실패하면 **조사를 시작하지 말고** 그 오류 한 줄만 보고하고 끝낸다.
  (조사를 다 하고 마지막 push에서 막히면 그날 사용량이 전부 버려진다.)

## 1. 오늘의 계획

```bash
python3 collector/collect.py --brief
```

출력은 세 부분이다.
1. **이번 회차에 조사할 미션** — 미션마다 검색어(이미 이번 달·다음 달로 채워져 있다)와 열어 볼 페이지.
2. **재확인할 행사** — 앞으로 7일 안의 `보도`·`추정` 행사 중 아직 재확인하지 않은 것 몇 건.
3. **이미 아는 행사** — 달력에 이미 있는 앞으로의 행사(`collector/cache/known.tsv`와 같은 내용).

## 2. 조사

계획에 나온 미션을 차례로 조사한다.

1. 미션의 검색어를 하나씩 검색한다. 결과 요약에서 행사를 찾으면 '이미 아는 행사'와 날짜·제목을 맞춰 본다.
   - 이미 아는 행사 → 건너뛴다.
   - 처음 보는 행사 → 날짜·시간·장소·신청이 요약에 다 있으면 그대로 적고, 빠진 게 있으면 기사 제목·기관명·연사 이름으로 **한 번만** 더 검색한다.
2. `열람:` 페이지는 WebFetch로 연다. 막혀 있으면(EGRESS_BLOCKED, 403 등) 바로 건너뛰고 그 URL을 inbox의 `blocked_urls`에 적는다.
   다음부터 계획에서 빠진다.
3. **재확인할 행사**는 건마다 공식 공지를 한 번 검색한다. 확인되면 같은 제목·날짜로 inbox에 적고 `confidence`를 `확정`으로,
   시간·신청 정보를 채운다. 확인되지 않으면 아무것도 적지 않는다(같은 행사를 다시 재확인하지 않도록 기록은 `collect.py`가 한다).

**찾는 것**: 오늘부터 계획 첫 줄의 범위 안에 **서울·청주** 또는 **온라인**으로 열리는
문학·글쓰기·철학·인문학 북토크, 작가와의 만남, 강연, 강좌, 낭독회, 대담, 워크숍.
도서전·독서대전·북페스티벌 안의 강연과 북토크는 각각 따로 적는다. 무료·유료 모두 포함한다.

**규칙**
- 지난 행사와 서울·청주 밖의 **오프라인** 행사는 버린다.
- **온라인 행사**(줌·유튜브 라이브·인스타 라이브 등)는 주최 지역과 상관없이 포함한다. `city`는 `온라인`, `venue`에 플랫폼(예: `줌`, `유튜브 라이브`)을 적는다.
  오프라인과 온라인을 함께 하면 오프라인 도시로 적고 `summary`에 '온라인 동시 진행'을 덧붙인다.
- 예스24·알라딘 작가와의 만남은 사용자가 가장 자주 챙겨 보는 곳이다. 어린이 그림책·학습서·재테크처럼 관심 밖 행사도
  일단 적되 `audience`/`relevance`로 낮게 매긴다(점수가 걸러 준다).
- 기사가 **작년 행사**를 다루는지 연도를 반드시 확인한다. 작년 일정을 올해로 옮겨 적지 않는다.
- 시리즈 강연은 회차마다 날짜·연사를 따로 한 건씩 적는다.
- 날짜를 하루로 특정할 수 없으면 적지 않는다(달력에 올릴 수 없다).
- 지어내지 않는다. 모르는 칸은 빈 문자열로 둔다.
- 기사·보도자료·SNS 공지 어느 하나에서라도 날짜(올해)와 장소가 나오면 기록한다. 그런 행사는 `confidence`를 `보도`로 적는다.

## 3. 기록

**새로 찾은 행사와 재확인된 행사만** `collector/inbox.json`에 쓴다. 아무것도 없으면 `{"events": []}`로 둔다.

```json
{
  "events": [
    {
      "source": "서울 서점 북토크",
      "title": "보라토크 — 이정우 ‘사람이란 무엇인가’",
      "date": "2026-10-17",
      "start": "14:00",
      "end": "15:30",
      "city": "서울",
      "venue": "광화문 교보빌딩 23층 대산홀",
      "speakers": ["이정우"],
      "book": "",
      "categories": ["철학", "인문"],
      "format": "강연",
      "audience": "성인",
      "festival": "",
      "price": "무료",
      "price_note": "",
      "registration": "교보문고 문화공간 페이지에서 신청",
      "url": "https://store.kyobobook.co.kr/culture/bora-show/859",
      "summary": "AI 시대에 다시 떠오른 존재론적 질문을 의학·철학·뇌과학을 넘나들며 묻는 강연.",
      "confidence": "확정",
      "relevance": 0.7,
      "speaker_weight": 0.45
    }
  ],
  "blocked_urls": []
}
```

| 칸 | 값 |
|---|---|
| `source` | 미션 이름 (재확인한 행사는 `재확인`) |
| `date` / `start` / `end` | `YYYY-MM-DD` / `HH:MM`(24시간). 모르면 `""` |
| `city` | `서울`, `청주`, `온라인` 중 하나 |
| `categories` | `글쓰기` `문학` `철학` `인문` 중 하나 이상 |
| `format` | `북토크` `강연` `강좌` `대담` `낭독회` `워크숍` `축제` `기타` |
| `audience` | `성인` `누구나` `가족` `청소년` `어린이` `제한`(특정 학교 구성원·지역 주민만) |
| `price` | `무료` `유료` `미확인` |
| `confidence` | 공식 공지 확인 `확정` · 기사 보도만 `보도` · 일부 추정 `추정` |
| `relevance` | 독자(문예창작 연구자)에게 도움이 될 가능성 0~1. 글쓰기·창작 직접 관련 0.85↑, 문학 작품 읽기 0.7~0.9, 철학 0.7~0.85, 일반 인문 0.4~0.7, 과학·자기계발·육아 0.3↓ |
| `speaker_weight` | 연사가 문학·인문 분야에서 갖는 무게감 0~1. 모르면 0.5 |
| `summary` | 무슨 이야기를 하는 자리인지 1~2문장 |

## 4. 병합과 저장

```bash
python3 collector/collect.py --ingest collector/inbox.json
```

지역·날짜를 다시 거르고, 기존 일정과 중복을 합치고, 점수를 매겨 `site/data/events.json`·`site/calendar.ics`를 쓴다.
새 행사에는 처음 발견한 날(`first_seen`)이 붙어 달력의 **'이번 주 새로 추가된 행사'** 코너에 나온다.
오늘 조사한 미션의 마지막 조사 회차·검색어 순번, 막힌 URL, 재확인 기록은 `collector/cache/state.json`에,
이미 아는 행사 목록은 `collector/cache/known.tsv`에 저장된다. 새 행사가 없어도 이 명령은 실행한다.
JSON 오류가 나면 `inbox.json`을 고쳐 다시 실행한다.

## 5. 게시

```bash
git add site/data/events.json site/calendar.ics collector/cache/state.json collector/cache/known.tsv
git commit -m "일정 갱신 $(TZ=Asia/Seoul date '+%F %H:%M')"
git push origin main
```

`main`에 push하면 GitHub Actions가 사이트를 다시 배포한다. **이 저장소에서는 `main`에 직접 push하는 것이 정해진 절차다.**
`inbox.json`과 `collector/cache/plan.json`은 커밋하지 않는다(.gitignore에 있음). 이 문서와 코드는 고치지 않는다.

- push가 거절되면(non-fast-forward) `git pull --rebase origin main` 후 한 번만 다시 시도한다.
- push가 403이면 다시 시도하지 말고 그 사실을 보고한다.

## 6. 보고

마지막 답변은 두 줄로 쓴다: 새로 추가된 행사 수(와 제목 한두 개), push 성공 여부.
